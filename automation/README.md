# Automation and load-test status

Browser smoke automation has been drafted for candidate review and execution. The assignment permits AI assistance with code but requires the candidate to run or review every test against the app. AI has not run this automation or operated the application.

## Browser automation

The Playwright suite uses environment variables for credentials and writes sanitized failure evidence to `test-results/`.

### One-command setup and execution

From the repository root:

```powershell
Set-Location .\b2b-marketplace-qa-assignment
npm install
npx playwright install chromium
npm run test:browser
```

Set credentials in the shell or process environment rather than committing them:

```powershell
$env:WC_PASSWORD = "Test@123"
$env:WC_BUYER_USERNAME = "buyer1"
$env:WC_SELLER_USERNAME = "seller1"
$env:WC_OPERATOR_USERNAME = "operator"
npm run test:browser
```

The suite must be reviewed before execution. It is intentionally a UI smoke and authentication harness, not a defect oracle. It does not call application APIs or change data through automation.

## Suggested regression automation order

1. Read-only API contract checks for login outcomes, buyer catalogue/search, and role-specific resource scoping.
2. Deterministic buyer cart and checkout calculations with controlled products, verifying per-seller minimum, tax rounding, fee, order split, and idempotent submission.
3. Seller status-transition and buyer-visible status checks.
4. Invoice and statement checks after creating and delivering controlled orders.
5. CSV import/export and partner API pagination/ownership checks.
6. UI smoke coverage for login, browse, checkout, order history, seller actions, and operator flows.

Before automating state-changing cases, identify safe test data, account isolation, and a cleanup/reset process. Store credentials in local environment variables or a secret store, never in source control or evidence.

## Load test requirements

- NF-01: 30 concurrent buyers; checkout p95 completion <=3 seconds.
- NF-02: search p95 response <=2 seconds.
- NF-03: monitor `/api/metrics`; do not exceed 50 requests/second. The brief says higher request rates return HTTP 429, but testing above the cap requires explicit environment-owner approval.
